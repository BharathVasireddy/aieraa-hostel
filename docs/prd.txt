# Aieraa Overseas Studies - Food Ordering App
## Product Requirements Document (PRD)

---

## 1. Product Overview

### 1.1 Product Name
**Aieraa Food** - Hostel Food Ordering System

### 1.2 Product Vision
A comprehensive food ordering Progressive Web Application (PWA) for Aieraa Overseas Studies hostels across Vietnamese universities, enabling seamless food ordering without delivery services.

### 1.3 Target Users
- **Primary**: Hostel students studying in Vietnamese universities
- **Secondary**: Hostel managers, food servers, system administrators

### 1.4 Business Context
- Company: Aieraa Overseas Studies (India-based)
- Operation: Multiple hostels across Vietnamese universities
- Structure: Boys/Girls hostels per university (2+ hostels per gender possible)
- Geography: Vietnam
- Service Model: No delivery - pickup only from hostel food counters

---

## 4. Detailed Feature Specifications

### 4.1 Authentication System

#### Student Registration Flow
1. **Form Fields:**
   - University (auto-populated dropdown from admin-created list)
   - Full name (required, min 2 words)
   - Email (required, unique, validation)
   - Phone (required, format validation)
   - Student block (required, text input)
   - Room number (required, alphanumeric)
   - University student ID (required, unique per university)
   - Password (required, min 8 chars, 1 uppercase, 1 number)

2. **Validation Rules:**
   - Email uniqueness across entire system
   - Student ID uniqueness within university
   - Phone number format: Vietnamese standards
   - All fields mandatory

3. **Approval Process:**
   - Registration creates "pending" user account
   - Manager receives notification of new registration
   - Manager reviews and approves/rejects
   - Student receives email notification of approval status
   - Only approved students can login

#### Login System
- **Methods**: Email + Password
- **Additional**: Biometric login (fingerprint/face ID) after first login
- **Session**: JWT tokens with refresh mechanism
- **Security**: Failed attempt lockout (5 attempts, 15-minute lockout)

### 4.2 Menu Management System

#### Menu Item Structure
```typescript
MenuItem {
  id: string
  university_id: string
  name: string
  description: string
  price: number (Vietnamese Dong)
  image_url?: string
  category: string
  is_veg: boolean // true for veg, false for non-veg
  daily_availability: DailyAvailability[]
  is_active: boolean
  created_by: string (manager_id)
  created_at: timestamp
  updated_at: timestamp
}

DailyAvailability {
  date: string (YYYY-MM-DD)
  available_quantity: number
  remaining_quantity: number
}
```

#### Manager Menu Features
- **CRUD Operations**: Create, read, update, delete menu items
- **Bulk Upload**: CSV/Excel import for multiple items
- **Image Management**: Upload and manage food images
- **Daily Availability**: Set quantity limits for each item per date
- **Categories**: Organize items (Breakfast, Lunch, Dinner, Snacks, Beverages)
- **Veg/Non-Veg**: Mandatory classification
- **Pricing**: Support for Vietnamese Dong currency
- **Preview**: See menu as students would see it

### 4.3 Order Management System

#### Order Structure
```typescript
Order {
  id: string
  student_id: string
  university_id: string
  order_date: timestamp (when order was placed)
  delivery_date: string (YYYY-MM-DD) // date for pickup
  items: OrderItem[]
  total_amount: number
  payment_method: 'online' | 'cash'
  payment_status: 'pending' | 'paid' | 'failed'
  order_status: 'pending' | 'approved' | 'cancelled' | 'ready' | 'served'
  qr_code: string
  approved_by?: string (manager_id)
  approved_at?: timestamp
  served_by?: string (server_id)
  served_at?: timestamp
  special_instructions?: string
  created_at: timestamp
}

OrderItem {
  id: string
  order_id: string
  menu_item_id: string
  menu_item_name: string // snapshot
  quantity: number
  unit_price: number // snapshot
  total_price: number
  status: 'active' | 'cancelled' // individual item can be cancelled
}
```

#### Student Order Flow
1. **Date Selection**: Choose delivery date (tomorrow onwards, within cutoff time)
2. **Menu Browsing**: View available items for selected date
3. **Cart Management**: Add/remove items, adjust quantities
4. **Order Review**: Confirm items, quantities, total amount
5. **Payment Selection**: Choose online payment or cash to manager
6. **Order Confirmation**: Receive order ID and estimated timeline

#### Manager Order Management
1. **Order Dashboard**: View all pending orders with filters
2. **Order Details**: Complete order information including:
   - Student details (name, room, block)
   - Order items and quantities
   - Order timing (placed when, for which date)
   - Payment method and status
   - Special instructions
3. **Bulk Actions**: Select multiple orders for approval
4. **Individual Actions**: Approve/cancel entire orders or individual items
5. **Payment Management**: Mark cash payments as received
6. **Status Updates**: Change order status (approved → ready → served)

#### Cutoff Time Logic
- **Configuration**: Manager sets cutoff time per university (e.g., 10 PM)
- **Validation**: Students cannot place orders after cutoff for next day
- **Display**: Show remaining time until cutoff
- **Timezone**: All times in Vietnam timezone

### 4.4 Payment System

#### Payment Methods
1. **Online Payment**
   - Integration with Vietnamese payment gateways
   - Support for major local payment methods
   - Real-time payment status updates
   - Automatic order approval after successful payment

2. **Cash Payment**
   - Order marked as "payment pending"
   - Manager interface to mark payments as received
   - Cash collection tracking for managers

#### Payment Flow
```
Online: Place Order → Payment Gateway → Success/Failure → Auto-approve if success
Cash: Place Order → Manager Review → Approve → Cash Collection → Mark as Paid
```

### 4.5 QR Code System

#### QR Code Generation
- **Unique Code**: Generated per order using order ID + security hash
- **Content**: Encrypted order details (order_id, student_id, date, amount)
- **Display**: Prominently shown in order details screen
- **Refresh**: New QR for each order, non-reusable

#### Server Scanning Process
1. **Scanner Interface**: Camera-based QR scanner
2. **Validation**: Verify QR code authenticity and order status
3. **Order Display**: Show order details after successful scan
4. **Status Update**: Mark order as "served" with timestamp
5. **Confirmation**: Visual/audio confirmation of successful scanning

## 5. Database Schema

### 5.1 Core Tables

```sql
-- Universities
CREATE TABLE universities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    location TEXT,
    cutoff_time TIME DEFAULT '22:00:00',
    timezone VARCHAR(50) DEFAULT 'Asia/Ho_Chi_Minh',
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Users (all roles)
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role user_role NOT NULL,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    phone VARCHAR(20),
    university_id UUID REFERENCES universities(id),
    
    -- Student specific fields
    student_block VARCHAR(50),
    room_number VARCHAR(20),
    university_student_id VARCHAR(100),
    
    -- Status
    account_status user_status DEFAULT 'pending',
    approved_by UUID REFERENCES users(id),
    approved_at TIMESTAMP,
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    
    -- Constraints
    CONSTRAINT unique_student_id_per_university 
        UNIQUE(university_student_id, university_id)
);

-- Enums
CREATE TYPE user_role AS ENUM ('student', 'manager', 'server', 'admin');
CREATE TYPE user_status AS ENUM ('pending', 'active', 'suspended', 'inactive');

-- Hostels
CREATE TABLE hostels (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    university_id UUID REFERENCES universities(id),
    name VARCHAR(255) NOT NULL,
    hostel_type hostel_type NOT NULL,
    warden_id UUID REFERENCES users(id),
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TYPE hostel_type AS ENUM ('boys', 'girls');

-- Menu Items
CREATE TABLE menu_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    university_id UUID REFERENCES universities(id),
    name VARCHAR(255) NOT NULL,
    description TEXT,
    price DECIMAL(10,2) NOT NULL,
    image_url TEXT,
    category VARCHAR(100) NOT NULL,
    is_veg BOOLEAN NOT NULL,
    is_active BOOLEAN DEFAULT true,
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Daily Availability
CREATE TABLE menu_item_availability (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    menu_item_id UUID REFERENCES menu_items(id),
    available_date DATE NOT NULL,
    available_quantity INTEGER NOT NULL DEFAULT 0,
    remaining_quantity INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    
    CONSTRAINT unique_item_date UNIQUE(menu_item_id, available_date)
);

-- Orders
CREATE TABLE orders (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    order_number VARCHAR(50) UNIQUE NOT NULL, -- Human readable order number
    student_id UUID REFERENCES users(id),
    university_id UUID REFERENCES universities(id),
    
    -- Timing
    order_date TIMESTAMP DEFAULT NOW(),
    delivery_date DATE NOT NULL,
    
    -- Pricing
    subtotal DECIMAL(10,2) NOT NULL DEFAULT 0,
    tax_amount DECIMAL(10,2) DEFAULT 0,
    total_amount DECIMAL(10,2) NOT NULL DEFAULT 0,
    
    -- Payment
    payment_method payment_method NOT NULL,
    payment_status payment_status DEFAULT 'pending',
    payment_reference VARCHAR(255),
    
    -- Order Status
    order_status order_status DEFAULT 'pending',
    
    -- QR Code
    qr_code TEXT UNIQUE NOT NULL,
    
    -- Approval
    approved_by UUID REFERENCES users(id),
    approved_at TIMESTAMP,
    
    -- Serving
    served_by UUID REFERENCES users(id),
    served_at TIMESTAMP,
    
    -- Additional
    special_instructions TEXT,
    cancellation_reason TEXT,
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Enums for Orders
CREATE TYPE payment_method AS ENUM ('online', 'cash');
CREATE TYPE payment_status AS ENUM ('pending', 'paid', 'failed', 'refunded');
CREATE TYPE order_status AS ENUM ('pending', 'approved', 'cancelled', 'ready', 'served');

-- Order Items
CREATE TABLE order_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    order_id UUID REFERENCES orders(id),
    menu_item_id UUID REFERENCES menu_items(id),
    
    -- Snapshot data (in case menu item changes)
    menu_item_name VARCHAR(255) NOT NULL,
    menu_item_description TEXT,
    unit_price DECIMAL(10,2) NOT NULL,
    
    -- Order specific
    quantity INTEGER NOT NULL DEFAULT 1,
    total_price DECIMAL(10,2) NOT NULL,
    item_status item_status DEFAULT 'active',
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    
    CONSTRAINT positive_quantity CHECK (quantity > 0)
);

CREATE TYPE item_status AS ENUM ('active', 'cancelled');

-- User University Assignments (for servers and managers)
CREATE TABLE user_university_assignments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    university_id UUID REFERENCES universities(id),
    assigned_by UUID REFERENCES users(id),
    assigned_at TIMESTAMP DEFAULT NOW(),
    is_active BOOLEAN DEFAULT true,
    
    CONSTRAINT unique_user_university UNIQUE(user_id, university_id)
);

-- Notifications
CREATE TABLE notifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    title VARCHAR(255) NOT NULL,
    message TEXT NOT NULL,
    notification_type notification_type NOT NULL,
    is_read BOOLEAN DEFAULT false,
    data JSONB, -- Additional data payload
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE TYPE notification_type AS ENUM (
    'order_status', 'payment_status', 'registration_status', 
    'promotional', 'system_alert', 'reminder'
);
```

### 5.2 Indexes for Performance

```sql
-- User indexes
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role_university ON users(role, university_id);
CREATE INDEX idx_users_status ON users(account_status);

-- Order indexes

CREATE INDEX idx_orders_university_status ON orders(university_id, order_status);
CREATE INDEX idx_orders_delivery_date ON orders(delivery_date);
CREATE INDEX idx_orders_qr_code ON orders(qr_code);

-- Menu item indexes
CREATE INDEX idx_menu_items_university ON menu_items(university_id, is_active);

-- Notification indexes
CREATE INDEX idx_notifications_user_unread ON notifications(user_id, is_read);
```

## 8. Business Rules & Validations

### 8.1 Order Placement Rules
1. **Timing**: Orders only accepted before daily cutoff time
2. **Date Range**: Orders for tomorrow to maximum 7 days ahead
3. **Quantity Limits**: Cannot exceed available quantity per item
4. **Single Date**: One order per date (separate orders for different dates)
5. **Minimum Order**: No minimum order value requirement
6. **Maximum Order**: Optional maximum order value per student

### 8.2 Payment Rules
1. **Online Payment**: Immediate order approval after successful payment
2. **Cash Payment**: Requires manager approval + cash collection
3. **Refunds**: Only for cancelled orders (if paid online)
4. **Currency**: All prices in Vietnamese Dong (VND)

### 8.3 Approval Workflow
```
Student Order → Manager Review → Approved → Kitchen Preparation → Ready → Served
```

**Cancellation Points:**
- Student: Before manager approval
- Manager: At any time before "Ready" status
- System: Automatically after 2 hours of "Ready" status

### 8.4 Data Validation Rules
1. **Email**: Valid format + unique across system
2. **Phone**: Vietnamese phone number format
3. **Student ID**: Unique within university
4. **Room Number**: Alphanumeric, university-specific format
5. **Prices**: Positive numbers with 2 decimal places
6. **Quantities**: Positive integers only

## 9. Security Requirements

### 9.1 Authentication Security
- **Password Policy**: Minimum 8 characters, 1 uppercase, 1 number, 1 special character
- **Session Management**: JWT tokens with 24-hour expiry
- **Failed Login Protection**: 5 attempts lockout for 15 minutes
- **Password Reset**: Email-based secure reset flow

### 9.2 Data Protection
- **Encryption**: All passwords hashed using bcrypt
- **HTTPS**: Enforce SSL/TLS for all communications
- **Input Sanitization**: Prevent SQL injection and XSS attacks
- **File Uploads**: Validate file types and sizes for menu images

### 9.3 Role-Based Access Control
- **Student**: Access only own university menu and orders
- **Manager**: Access only assigned university data
- **Server**: Access only today's ready orders for assigned universities
- **Admin**: Full system access with audit logging

### 9.4 QR Code Security
- **Encryption**: QR codes contain encrypted order information
- **Expiry**: QR codes expire after order completion or 24 hours
- **Uniqueness**: Each QR code is single-use and order-specific
